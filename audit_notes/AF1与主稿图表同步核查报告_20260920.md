## 四、不一致项（需处理）

### 🔴 P0-1：AF1 末尾存在一张**重复的 Fig. S1 图**（无图注）

**位置**：AF1 文档 `w:body` 索引 112，即 **Table S21 表体之后、`Table S22` 题注之前**。

**证据链**

| 证据 | 实测 |
|---|---|
| 引用总数 ≠ 媒体数 | `r:embed` = **7**，`word/media/` = **6** |
| 该处的 rId | `rId7` → `word/media/image1.png` |
| `image1.png` 的服务对象 | 它**同时**被 slot 1（文档开头 Figure S1）与 slot 7（此处）引用 |
| 图片尺寸 | slot 7 = `5486400 × 5293714` EMU（15.24 × 14.7 cm），与 slot 1 **完全一致** |
| 该处图注 | **无**（其后紧接的段落是 `Table S22. Composition of the harmonised eQTLGen whole-blood arm…`） |
| MD5 对照 | `image1.png` = `c1d052c38d562805f211692ab105fe0c` = 磁盘 `FigS1.png` |

**性质**：这是同一张 Fig. S1 流程图在文中出现的**第二份**，且无任何图注支持。它使 AF1 的自我声明
（"Supplementary figures are embedded in this file"）与"每图一份"不符，审稿人翻看时会在两张表之间看到一张无标注的重复图。

**需更新的部分**：删除该图片段落（含其承载的空段落）。**不涉及**任何数值、编号或图注变更。

> 若该处本意是给某张表配图，则应改为插入对应图并补图注——但从上下文（Table S21 是 TUBB 排除的敏感性分析，Table S22 是基因模型 SNP 清单）看，两张表都不需要配图，故判定为误插。

### 🟡 P1-1：仓库 README §Overview 的 Stouffer/ACAT-O 表述（**本轮已修正**，非 AF1 问题）

本次审计中顺带发现：仓库 README 在上一轮被改成"dual-mismatch arm 现在也用 ACAT-O"，**与主稿直接矛盾**。主稿证据：

- p39「Because ACAT-O combines two-sided tissue-level P values, **the combined statistic carries no intrinsic direction, so it is used only for the direction-free enrichment endpoint**」
- p94 Table 3 题注「the primary multi-tissue statistic for candidates is the ACAT-O omnibus P value, **which carries no intrinsic direction**; candidate genes do enter the two arms **whose GTEx side is signed**」
- Table 3c 第 5 行「Candidate genes only (dual arm; **GTEx multi-tissue Stouffer Z** vs eQTLGen)」
- AF1 Table S10「The multi-tissue side is **Stouffer's weighted-Z estimate, which carries an intrinsic direction**, so candidates can be assigned a sign in this arm」

⇒ 正确口径是**分工**而非替代：

| 用途 | 估计量 | 原因 |
|---|---|---|
| FDR 富集 / P 值端点（Table 1、Table 2、Table S2 的 q） | **ACAT-O**（primary） | 方向无关 |
| dual-mismatch 臂的方向一致性 / 相关性 | **Stouffer weighted Z**（`Z_multi_tissue`） | ACAT-O 无方向，无法赋符号 |

已在本轮提交 `14d2289` 修正 README，恢复原归属并写明分工。
